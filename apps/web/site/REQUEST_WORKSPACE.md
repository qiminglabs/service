# 服务请求提交后工作区

## 客户确认

- 客户中心待确认请求提供“确认”和“拒绝”按钮。确认后进入待受理；拒绝必须填写原因，退回第四步“客户确认”（请求状态回到待评估以允许重新发起）。
- 拒绝保留材料结论、核定人天、服务依据、资产锁定和审批结果，仅清除本次待确认标记；项目经理可直接再次发起客户确认。第四步展示全部拒绝历史，包括姓名、日期时间及原因。
- 保存层核对所属客户、当前待确认状态和原方案，防止重复或过期决定；记录客户姓名、时间与拒绝原因。仍为本机原型，不发送外部通知。

## 当前评估规则（四步骤，取代下方历史流程说明）

- 评估显示“材料评估、核定人天、关联服务依据、客户确认”四个步骤。评估历史归入材料评估底部；处理审批按钮使用蓝色。发起客户确认先打开二次确认弹窗，仅展示请求概览和预计消耗客户资产，不展示特批或内部评估工时；点击“确认发起”后才保存并进入待确认。
- 取消待办创建、指派、反馈、附件及完成校验；旧待办数据只保留原始数据，不参与流程或访问授权。
- 材料未通过前可继续记录评估，通过后永久锁定当前提交周期的材料结论，不支持新增评估或退回重新评估。
- 人天单独核定后方可关联服务依据；调整核定人天会释放原资产预留并使旧特批失效，但不改变材料评估通过结论。资产不足仍由销售发起、上级审批。
- 待评估阶段，负责项目经理可在服务请求右上角“退回草稿”，填写退回原因；其他角色及其他阶段不可操作。保存层再次验证操作者、状态和操作记录。
- 退回时释放资产、失效相关特批、归档本周期评估，保留活动历史；草稿可修改申请材料，重新提交后开始新提交周期。

## 2026-09-08 评估流程更新（取代下方旧评估及特批规则）

- 销售或客户提交后，分配到启用的项目经理。项目经理独立记录多轮评估结论，管理员和协作人不能代为评估。
- 每轮保存服务范围、意见、风险及“需补充 / 评估通过”结论；需补充时分配“补充材料 / 联系客户”待办。负责人提交处理结果和附件后，由项目经理再次评估；未反馈待办会阻止评估通过。
- 评估通过后核定总人天、选择客户资产及负责销售。主数据服务资产增加“余额人天（含已锁定）”；历史空余额不推断。保存方案和发起确认时，在同一 IndexedDB 事务读取最新资产及全部请求，校验可锁定余额，避免本设备请求之间重复占用。
- 资产不足由指定销售发起额度特批，交另一位员工或管理员审批；销售及负责评估的项目经理不能自行审批。当前目录没有上下级关系，由销售指定上级审批人。
- 拒绝保留历史并允许重新发起；调整方案使旧方案特批失效。退回重新评估释放资产、失效旧特批，并要求完成新一轮评估。
- 足额覆盖后，由项目经理发起客户确认，状态进入待确认并保存服务范围与总人天快照。客户仅查看方案和总人天，不展示内部意见及特批原因。
- 销售、待办负责人及指定审批人获得请求访问权；无关员工不获得访问权。旧评估和依据只读保留。
- 本次仍为设备本地原型：未扣减生产资产、未发送客户通知、未实现客户最终签署；本地锁定不等于跨设备生产冻结。资产取消时释放，已转服务项目仍保留占用。
- 验证入口：赵言记录评估及锁定方案；有缺口时王琪发起特批，指定上级（如陆明）审批，最后赵言发起客户确认。资产余额需先按实际情况维护。
- 内部工时现为日期、起止时间、类型及内容，按分钟换算小时；自己的有效记录可编辑或作废。会议已保存附件可删除并留痕。

本次为现有设备本地原型扩展。没有发布站点、同步 GitHub、通知客户、创建真实会议或扣减资产。

## 页面与数据

- 草稿沿用现有申请页。提交后在左侧主区显示：申请信息、会议、评估记录、内部工时、活动；服务依据在评估记录内管理，不再单独显示页签。
- 内外部协作人在右侧常驻，修改即保存并记入活动；不受申请信息只读影响。
- 基本信息、申请项及材料保持只读；保存层再次检查基本字段和申请项，防止误改。
- 新模块保存在请求的 `operations` 下，沿用 IndexedDB，不单独创建第二份请求。历史记录按需初始化为空，不植入虚假会议、工时或审批。
- 客户与合作伙伴服务工程师不展示内部工作页签或内部协作人。右上角仅选择固定用户，角色由用户编号确定，不允许自由组合；仅用于本地演示，不是生产权限控制。

### 固定身份与旧数据兼容

角色统一为：SmartX 系统管理员、SmartX 员工、SmartX 项目经理、SmartX 服务工程师、合作伙伴服务工程师、客户。

- 陆明：SmartX 系统管理员；王琪、陈屿、周遥、许安：SmartX 员工；赵言：SmartX 项目经理；林澈：SmartX 服务工程师；顾远：合作伙伴服务工程师；沈宁：客户。
- 原销售、售前、PMO、审批人归入 SmartX 员工。员工与管理员承接评估、特批和审批；仍须指定另一位用户审批，禁止自批。
- 旧目录只补齐缺失用户，不覆盖姓名、部门、停用状态或自建用户；保留用户编号，因此协作人、工时和审批人员关联不变。
- 请求创建人、目录创建人和活动中的旧角色占位名称按新名称显示，真实人名和历史审计原文不重写。合作伙伴与客户不混入内部用户查找。

## 操作规则

| 模块 | 本地实现 |
| --- | --- |
| 会议 | 预约/开始/结束模拟会议、查看会议时间及参会人、只读转写；空白或 test 占位显示标注的模拟转写。主持人或管理员可上传多个普通附件（每个不超过 20 MB），保留同名文件并支持下载；不再显示录制区或转写编辑框 |
| 内部工时 | 当前内部协作人录入自己的日期、小时数、工作类型、工作内容；最小 0.25 小时，同一请求同一成员同一天合计不超过 24 小时；错误记录作废留痕，再重新录入 |
| 评估记录 | SmartX 员工/管理员保存范围、意见、风险、预计人天和审批人；草稿可编辑，提交后冻结评估内容；指定另一位有审批权限的用户处理 |
| 活动 | 记录提交、协作人调整、会议、工时、依据变化、评估及审批；按类型筛选，保存时不允许改写已有活动 |
| 服务依据 | SmartX 员工/管理员关联本客户已启用资产及申请项、计划使用人天，人工核对有效期、余额和适用范围；提交特批后由指定其他人审批，拒绝记录保留 |

### 评估与特批

- 评估提交前要求所有申请项有有效依据覆盖，依据计划人天合计不小于评估人天。
- 资产关联不等于已核对，更不等于实际冻结、扣减；当前资产数据没有余额字段，核对意见由 PMO 输入。生产版需对接资产余额和冻结接口。
- 评估提交保留当时的依据编号，审批通过前再次检查覆盖关系和资产有效状态；审批中的依据不能直接移除。
- 状态顺序为草稿 → 待评估 → 待确认 → 待受理 → 已转服务项目；已取消不加入常规进度。既有待受理、已转服务项目记录保持原状态，不倒退。
- 同一时间只能有一个待审批评估。提交人不能自行审批。审批通过后请求进入待确认；拒绝后评估记录为已拒绝，请求继续待评估，可建立新一轮评估。本次仅插入状态并调整评估出口，客户确认表单及其操作暂未实现。
- 特批拒绝后保留原记录，可新建特批；拒绝不会取消整个服务请求。
- 本地审批不会发送外部消息或建立外部审批单。已转服务项目、已取消请求的工作模块只读，但仍允许内部人员维护协作人。

## 腾讯会议接入边界

本版**未嵌入真实腾讯会议 SDK**，模拟会议不产生腾讯会议号、入会链接、真实参会者、自动录制或自动转写。页面明确标注本地模拟。

正式接入时需要确认：

1. 企业应用的开通方式、SDK 支持的运行平台、应用标识及会议账号授权范围。
2. 后端安全保管应用密钥，签发短期授权；不得将长期密钥写入浏览器、仓库或 URL。
3. 会议创建/查询及回调，将会议 ID 与请求 ID 关联；回调校验、幂等和失败重试。
4. 云录制和转写权限、处理状态、到期/删除状态、短期访问链接；不将存在会议等同于必然存在录制。
5. 录制告知与授权、内部和外部参与者查看权限及数据保留策略。

- 选择一份已提交请求，在右侧加入内部协作人，再通过右上角菜单“切换用户”选择该成员录入工时；无单独角色选择器。
- 顶部选择周遥（SmartX 员工），关联资产并核对，再填写评估；也可选择王琪提交特批。
- 指定许安为审批人，切换至许安即可审批，无需再切换角色。拒绝必须说明原因，评估通过将状态更新为待确认。
- 会议页预约会议，开始并结束后即可查看转写和上传附件。旧转写原文不覆盖，旧录制仍以普通附件下载；刷新后文件保留。新会议记录实际模拟开始时间，并在开始时保存协作人名单快照。

自动测试：`node --test lib/request-operations.test.mjs lib/service-requests.test.mjs lib/online-material.test.mjs`。

- 会议预约、进行中及结束后均可上传和删除附件，沿用主持人/管理员权限；请求已转服务项目或已取消时只读。退回草稿后可通过会议页签维护已有会议附件。


- “评估记录”页签更名为“评估”；申请信息右侧增加“补充资料”。内部端与客户中心均可在草稿、待评估阶段发布评论或附件；内部发布可选择客户可见或仅内部可见。客户中心仅显示客户可见记录和数量，后续阶段只读。补充资料独立于申请项必填材料，不替代提交校验。

- 评估区域标题统一为“评估”。四步骤仅展示当前材料结论、核定人天、当前方案及最新审批状态，不显示归档评估、旧流程评估、往次材料结论和拒绝历史；历史通过活动查看，原始历史数据与活动记录保留。

## 待受理创建服务项目

- 待受理阶段，由负责项目经理在请求右上角“创建服务项目”。默认全部申请项归入一个项目，可新增项目、逐项或批量移动、合为一个项目、一项一项目；项目名称必填、说明选填。
- 每个申请项且仅生成一张工单，同一目录重复申请按申请项分别生成。全部申请项须分配完成，空项目须移除；创建前预览并确认。
- 项目与工单在同一请求保存事务中生成，保存层重新校验角色、待受理状态、源申请项与当前数据，防止重复或过期创建。创建后请求进入已转服务项目，项目待启动、工单待排期。
- 项目和工单数据保存在 operations.projectCreation，申请信息上方可展开查看项目及所属工单；工单保存独立申请项及材料快照，原确认方案和资产锁定保持。活动记录创建结果。
- 沿用设备本地原型，不创建外部系统项目；独立项目工作台、工单排期与执行流程后续实现。

- 创建项目界面简化为单页卡片：输入项目名称、新增项目，拖动申请项完成分组，不显示移动下拉菜单。取消批量工具栏、侧边汇总、项目说明输入和单独预览步骤，底部直接创建；空项目及漏项校验保留。
