# 服务请求提交后工作区

本次为现有设备本地原型扩展。没有发布站点、同步 GitHub、通知客户、创建真实会议或扣减资产。

## 页面与数据

- 草稿沿用现有申请页。提交后在左侧主区显示：申请信息、会议、内部工时、评估记录、活动、服务依据。
- 内外部协作人在右侧常驻，修改即保存并记入活动；不受申请信息只读影响。
- 基本信息、申请项及材料保持只读；保存层再次检查基本字段和申请项，防止误改。
- 新模块保存在请求的 `operations` 下，沿用 IndexedDB，不单独创建第二份请求。历史记录按需初始化为空，不植入虚假会议、工时或审批。
- 客户与合作伙伴服务工程师不展示内部工作页签或内部协作人。右上角仅选择固定用户，角色由用户编号确定，不允许自由组合；仅用于本地演示，不是生产权限控制。

### 固定身份与旧数据兼容

角色统一为：SmartX 系统管理员、SmartX 员工、SmartX 项目经理、SmartX 服务工程师、合作伙伴服务工程师、客户。

- 陆明：SmartX 系统管理员；王琪、陈屿、周遥、许安：SmartX 员工；赵言：SmartX 项目经理；林澈：SmartX 服务工程师；顾远：合作伙伴服务工程师；沈宁：客户。
- 原销售、售前、PMO、审批人归入 SmartX 员工。员工与管理员承接评估、特批和审批；仍须指定另一位用户审批，禁止自批。
- 旧目录只补齐缺失用户，不覆盖姓名、部门、停用状态或自建用户；保留用户编号，因此协作人、工时和审批人员关联不变。
- 请求创建人、目录创建人和活动中的旧角色占位名称按新名称显示，真实人名和历史审计原文不重写。合作伙伴与客户不混入内部用户查找。

## 操作规则

| 模块 | 本地实现 |
| --- | --- |
| 会议 | 发起/结束模拟会议、查看历史、导入不超过 20 MB 的 MP4/WebM、播放/下载录制、粘贴与查看已有转写；主持人或管理员归档资料 |
| 内部工时 | 当前内部协作人录入自己的日期、小时数、工作类型、工作内容；最小 0.25 小时，同一请求同一成员同一天合计不超过 24 小时；错误记录作废留痕，再重新录入 |
| 评估记录 | SmartX 员工/管理员保存范围、意见、风险、预计人天和审批人；草稿可编辑，提交后冻结评估内容；指定另一位有审批权限的用户处理 |
| 活动 | 记录提交、协作人调整、会议、工时、依据变化、评估及审批；按类型筛选，保存时不允许改写已有活动 |
| 服务依据 | SmartX 员工/管理员关联本客户已启用资产及申请项、计划使用人天，人工核对有效期、余额和适用范围；提交特批后由指定其他人审批，拒绝记录保留 |

### 评估与特批

- 评估提交前要求所有申请项有有效依据覆盖，依据计划人天合计不小于评估人天。
- 资产关联不等于已核对，更不等于实际冻结、扣减；当前资产数据没有余额字段，核对意见由 PMO 输入。生产版需对接资产余额和冻结接口。
- 评估提交保留当时的依据编号，审批通过前再次检查覆盖关系和资产有效状态；审批中的依据不能直接移除。
- 状态顺序为草稿 → 待评估 → 待确认 → 待受理 → 已转工单；已取消不加入常规进度。既有待受理、已转工单记录保持原状态，不倒退。
- 同一时间只能有一个待审批评估。提交人不能自行审批。审批通过后请求进入待确认；拒绝后评估记录为已拒绝，请求继续待评估，可建立新一轮评估。本次仅插入状态并调整评估出口，客户确认表单及其操作暂未实现。
- 特批拒绝后保留原记录，可新建特批；拒绝不会取消整个服务请求。
- 本地审批不会发送外部消息或建立外部审批单。已转工单、已取消请求的工作模块只读，但仍允许内部人员维护协作人。

## 腾讯会议接入边界

本版**未嵌入真实腾讯会议 SDK**，模拟会议不产生腾讯会议号、入会链接、真实参会者、自动录制或自动转写。页面明确标注本地模拟。

正式接入时需要确认：

1. 企业应用的开通方式、SDK 支持的运行平台、应用标识及会议账号授权范围。
2. 后端安全保管应用密钥，签发短期授权；不得将长期密钥写入浏览器、仓库或 URL。
3. 会议创建/查询及回调，将会议 ID 与请求 ID 关联；回调校验、幂等和失败重试。
4. 云录制和转写权限、处理状态、到期/删除状态、短期访问链接；不将存在会议等同于必然存在录制。
5. 录制告知与授权、内部和外部参与者查看权限及数据保留策略。

## 参考与适配

- [Jira Service Management：审批](https://support.atlassian.com/jira-service-management-cloud/docs/what-are-approvals/)：审批决定是否进入下一阶段。本地采用“评估记录独立审批、通过才推进请求”。
- [Jira Service Management：审批历史和活动](https://confluence.atlassian.com/servicemanagementserver104/setting-up-approvals-1528205883.html)：审批信息进入活动记录。本地将所有审批集中留痕，同时保留评估或特批自身记录。
- [Jira Service Management：工时记录](https://support.atlassian.com/jira-service-management-cloud/docs/log-time-on-an-issue/)：工作投入与请求关联。本地将投入小时和客户计费人天分开。
- [ServiceNow：请求审批](https://www.servicenow.com/docs/r/service-management-for-the-enterprise/c_RequestApprovals.html)：请求审批和补充信息处理。本地不照搬其状态名，沿用当前六种请求状态及“拒绝后保留待评估”的约定。
- [腾讯会议开放平台](https://meeting.tencent.com/open-api.html)、[腾讯会议官方 SDK 文档](https://github.com/Tencent-Meeting/TencentMeetingSDK)：实际 SDK/API、授权和会议产物能力的接入依据，不能由本地 UI 模拟替代。
