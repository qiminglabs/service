# 主数据对象字段表

本文件是主数据模块中 `Customer`、`Contact`、`Asset`、`BusinessObject` 和 `User` 对象的字段单一事实源。后续服务申请、服务项目、派单、工单，以及 Demo 管理页面的列表、表单、接口、数据库和测试数据，都必须使用本文件中的名称、类型、枚举与校验规则。

## 客户（Customer）

| 标准字段名 | 中文名称 | 类型 | 创建必填 | 来源 | 规则与说明 |
| --- | --- | --- | --- | --- | --- |
| `customerId` | 客户 ID | UUID / ID | 系统 | 系统生成 | 内部主键，全局唯一，不向普通用户编辑 |
| `customerCode` | 客户编码 | String | 系统 | 系统生成 | 格式 `CUS-{序号}`，全局唯一，创建后不可修改 |
| `customerName` | 客户名 | String(120) | 是 | 用户填写 | 去除首尾空格后不能为空 |
| `responsibleTeam` | 负责团队 | Enum | 是 | 用户选择 | `金融`、`商业`、`港澳`、`其他` |
| `status` | 状态 | Enum | 系统 | 系统维护 | `启用`、`停用`；创建后默认 `启用` |
| `createdBy` | 创建人 | User ID | 系统 | 系统记录 | 不可编辑 |
| `createdAt` | 创建时间 | DateTime | 系统 | 系统记录 | ISO 8601，展示时按用户时区格式化 |
| `updatedBy` | 上次修改人 | User ID | 系统 | 系统记录 | 不可编辑 |
| `updatedAt` | 上次修改时间 | DateTime | 系统 | 系统记录 | ISO 8601，展示时按用户时区格式化 |

## 编码规则

| 对象 | 编码格式 | 示例 |
| --- | --- | --- |
| 客户 | `CUS-{序号}` | `CUS-001` |
| 联系人 | `CON-{序号}` | `CON-001` |
| 资产 | `AST-{序号}` | `AST-001` |
| 业务对象 | `OBJ-{序号}` | `OBJ-001` |
| 用户 | `USR-{序号}` | `USR-001` |

序号默认使用三位，从 `001` 开始递增。编码仅由系统生成，前端、接口调用方和导入流程均不得自行指定或修改；数据库内部关联统一使用各对象 ID，不使用展示编码作为外键。

## 对象关系与引用约束

```text
Customer
├── Contact
├── Asset
└── BusinessObject

User
└── ServiceRequest.internalParticipants（内部协作人）
```

- 联系人、资产和业务对象都必须属于一个客户。
- 主数据页面不提供删除入口；所有对象通过“停用”保留历史记录。
- 停用记录不再出现在新建主数据或服务申请的可选项中，已有引用和历史展示不受影响。
- 服务申请中的内部协作人点击“添加”后在弹窗中通过姓名、邮箱或部门搜索已启用用户，支持多选、确认添加；仅保存用户 ID 和姓名，不再分配角色。历史角色字段不再展示或校验。
- 服务申请中的外部协作人点击“添加”后在弹窗中搜索当前客户的已启用联系人，可按姓名、手机号或邮箱匹配，支持多选、确认添加，并保存联系人快照；取消弹窗不修改协作人列表。
- 下游申请或工单引用主数据时，保存对象 ID，并保存业务展示所需的必要快照，避免主数据后续修改影响历史记录。
- 客户、联系人、资产、业务对象或用户被下游业务记录引用后，均不执行物理删除。
- `upgradeEntitlementQuantity` 与 `inspectionEntitlementQuantity` 分别独立校验，二者都不能超过 `nodeCount`。

## 设计与实现约束

- 页面文案统一使用“客户名”“负责团队”“所属客户”“资产名称”“对象名称”“SN”“产品”“节点数”“升级权益”“巡检权益”“姓名”“邮箱”和“部门”。
- 列表、创建表单、编辑表单、详情页、筛选条件、接口字段和测试数据必须与本文件一致。
- 创建操作要求填写各对象字段表中所有“用户填写”字段；系统字段由系统自动补齐。
- Demo 页面负责维护数据和演示引用关系，不拥有字段定义；字段变更应先更新本文件，再同步页面、接口和数据模型。
