# 主数据对象字段表

本文件是主数据模块中 `Customer`、`Contact`、`Asset`、`BusinessObject`、`User`（内部用户）、`Partner`、`PartnerUser` 和 `ServiceCertification` 对象的字段单一事实源。后续服务申请、服务项目、派单、工单，以及 Demo 管理页面的列表、表单、接口、数据库和测试数据，都必须使用本文件中的名称、类型、枚举与校验规则。

| --- | --- | --- | --- | --- | --- |

| `responsibleTeam` | 负责团队 | Enum | 是 | 用户选择 | `金融`、`商业`、`港澳`、`其他` |

## 合作伙伴用户（PartnerUser）

| 标准字段名 | 中文名称 | 类型 | 创建必填 | 来源 | 规则与说明 |
| --- | --- | --- | --- | --- | --- |
| `partnerUserId` | 合作伙伴用户 ID | UUID / ID | 系统 | 系统生成 | 唯一，不可编辑 |
| `partnerUserCode` | 合作伙伴用户编码 | String | 系统 | 系统生成 | `PUS-{序号}`，不可修改 |
| `userName` | 姓名 | String(80) | 是 | 用户填写 | 去除首尾空格后不能为空 |
| `partnerId` | 所属合作伙伴 | Partner ID | 是 | 用户选择 | 新建时必须引用已启用的合作伙伴 |
| `mobile` | 手机号 | String(11) | 是 | 用户填写 | 去除空格后符合中国大陆手机号格式 `^1\d{10}$` |
| `email` | 邮箱 | String(254) | 是 | 用户填写 | 有效邮箱；保存为小写，在合作伙伴用户中唯一 |
| `status` | 状态 | Enum | 系统 | 系统维护 | `启用`、`停用`；默认 `启用` |

新增两类记录沿用本机引用数据保存方式，提供 3 家合作伙伴和 5 名合作伙伴用户模拟数据。示例使用保留编号 `PAR-DEMO-{序号}`、`PUS-DEMO-{序号}`，避免与手动新建的数字编号冲突。加载时仅补齐缺失示例，保留已有记录、改名和停用状态，不重复添加。

合作伙伴停用后保留已有用户的关联，不级联修改用户状态，也不允许新建用户关联该伙伴。内部用户继续使用原 `users` 存储键和 ID，保留已有记录与服务申请引用。合作伙伴用户不混入内部用户或现有协作人选项。

### 本地身份切换

- 右上角“切换用户”只读取主数据中的姓名与 ID，不额外生成独立的人物身份。
- 切换菜单按角色去重，每种角色仅展示一名已启用人员；优先保留当前选中人员，其他角色按目录顺序取首位有效人员。该规则仅影响菜单，不删除主数据、不缩减审批或协作人候选名单。
- 内部身份来自已启用内部用户，沿用固定角色映射；“SmartX 员工”保留王琪（`USR-001`）、陈屿（`USR-002`）两条启用记录。周遥（`USR-005`）、许安（`USR-007`）停用但保留历史引用。
- “客户”身份来自已启用客户下的已启用联系人；“合作伙伴服务工程师”来自已启用合作伙伴下的已启用合作伙伴用户。
- 主数据改名立即反映到菜单；用户或所属组织停用后退出可选身份，不改变既有业务快照。
- 这只是本地 Demo 身份切换，不创建真实登录账号或改变生产权限。

## 服务认证（ServiceCertification）

| 标准字段名 | 中文名称 | 类型 | 创建必填 | 来源 | 规则与说明 |
| --- | --- | --- | --- | --- | --- |
| `id` | 记录编号 | ID | 系统 | 系统生成 | `CRT-{序号}`；样例保留 `CRT-DEMO-{序号}`，避免覆盖手工记录 |
| `certification` | 认证内容 | Enum | 是 | 用户单选 | 与服务目录认证要求共用字典：`SMTX OS 认证`、`CloudTower 认证`；`无认证要求`仅用于目录，不是个人认证 |
| `holderType` | 用户类型 | Enum | 是 | 用户单选 | `internal`（内部用户）、`partner`（合作伙伴用户） |
| `userId` | 认证用户 | User / PartnerUser ID | 是 | 用户选择 | 内部用户须已启用；合作伙伴用户及其所属合作伙伴均须已启用 |
| `userName` | 用户姓名快照 | String | 系统 | 主数据 | 创建时自动读取；列表优先显示主数据当前姓名，历史记录无法关联时回退快照 |
| `expiresOn` | 到期日 | Date | 是 | 用户选择 | 有效的 `YYYY-MM-DD` 日期，含到期日当天；允许补录历史已到期认证 |
| `status` | 状态 | Enum | 系统 | 系统维护 | `启用`、`停用`；新建默认启用，保留停用记录，不提供删除 |

- 一条记录对应一名用户的一项认证。同一用户、同一认证、同一到期日的启用记录不重复创建。
- 新增 3 条关联已有主数据的样例，覆盖内部用户和合作伙伴用户；加载时补齐缺失样例，保留已有日期及停用状态。示例仅用于本地 Demo，不代表真实资质。
- 服务认证与其余引用数据一同保存在本机；本次不改变服务申请或派单的认证校验规则。

## 对象关系与引用约束

```text
Customer
├── Contact
├── Asset
└── BusinessObject

User
└── ServiceRequest.internalParticipants（内部协作人）

Partner
└── PartnerUser
```

- 联系人、资产和业务对象都必须属于一个客户。
- 主数据页面不提供删除入口；所有对象通过“停用”保留历史记录。
- 停用记录不再出现在新建主数据或服务申请的可选项中，已有引用和历史展示不受影响。
- 服务申请中的内部协作人点击“添加”后在弹窗中通过姓名、邮箱或部门搜索已启用用户，支持多选、确认添加；仅保存用户 ID 和姓名，不再分配角色。历史角色字段不再展示或校验。
- 服务申请中的外部协作人点击“添加”后在弹窗中搜索当前客户的已启用联系人，可按姓名、手机号或邮箱匹配，支持多选、确认添加，并保存联系人快照；取消弹窗不修改协作人列表。
- 下游申请或工单引用主数据时，保存对象 ID，并保存业务展示所需的必要快照，避免主数据后续修改影响历史记录。
- 客户、联系人、资产、业务对象或用户被下游业务记录引用后，均不执行物理删除。
- `upgradeEntitlementQuantity` 与 `inspectionEntitlementQuantity` 分别独立校验，二者都不能超过 `nodeCount`。

## 设计与实现约束

- 页面文案统一使用“客户名”“负责团队”“所属客户”“资产名称”“对象名称”“SN”“产品”“节点数”“升级权益”“巡检权益”“姓名”“邮箱”和“部门”。
- 列表、创建表单、编辑表单、详情页、筛选条件、接口字段和测试数据必须与本文件一致。
- 创建操作要求填写各对象字段表中所有“用户填写”字段；系统字段由系统自动补齐。
- Demo 页面负责维护数据和演示引用关系，不拥有字段定义；字段变更应先更新本文件，再同步页面、接口和数据模型。
