# 申请项与评估材料：本地实现

## 用户操作

1. 在服务请求列表新建请求，主题（名称）、有效客户和该客户下已启用的联系人必填，校验通过后保存为草稿。切换客户清空联系人；无可用联系人时须先维护客户联系人。
2. 创建后客户只读，不支持变更；申请详情可补充主题、该客户联系人、期望服务日期和整体申请背景。期望服务日期选填，使用日期选择器，以 `YYYY-MM-DD` 随草稿保存，提交后只读；历史记录保持空值。历史未关联客户的草稿保留，但需重新创建请求。
3. 在“添加申请项”原弹窗中选择已启用目录，继续在同一弹窗填写具体需求、服务方式及该目录配置的参数。业务对象选填且可多选，仅可选择该客户的对象。
4. 点击“保存申请项”，基础字段校验通过后才创建申请项并关闭弹窗；材料不在该弹窗填写，也不作为保存申请项的前置条件。取消弹窗不产生空申请项。
5. 申请项不再展开材料。在“待补充：上传某材料”旁点击“补充材料”，打开该份材料的弹窗；已完成及选填材料也保留各自入口，不增加详情页标签或独立材料区。
6. 弹窗展示文件说明，提供下载模板、从模板开始在线填写、从空白开始在线填写、上传已有文件。进入在线填写后隐藏材料入口、文件说明与文件列表，切换为腾讯文档风格的本地富文本编辑器，支持标题、加粗、斜体、下划线、列表、撤销重做、目录与缩放；返回材料时保留未保存内容。此界面仅模拟文档 SDK 容器，不连接腾讯服务。实际配置的 DOCX/TXT/Markdown 模板读取正文，不保留原图片和版式；文档格式以结构化内容保存在本机，下载文件仍为 TXT。修改基础字段使用原弹窗。
7. 整单提交：任一必填内容不完整时明确列出缺项并保持草稿；通过校验并确认提交后进入待评估。

## 配置与归属

申请详情采用与服务目录一致的浅色背景和顶部摘要卡片，主体为 7:3 双栏布局。左侧展示基本信息、申请项和系统信息；右侧上方为外部协作人，下方为内部协作人。两类协作人均点击卡片上的“添加”打开搜索弹窗，多选后确认添加；取消不改变当前列表，已添加人员标记为“已添加”以避免重复。外部协作人搜索当前客户的已启用联系人，支持姓名、手机号和邮箱；内部协作人搜索引用数据中的已启用用户，支持姓名、邮箱和部门，不再分配角色，旧角色字段不再展示或校验。协作人按引用对象编号去重，随草稿保存，提交后只读。

系统信息只读展示创建时间、更新时间、提交时间、创建人；未提交显示“未提交”。原基本信息中的发起人移至此处，不重复展示。当前站点未接入身份认证，新记录保留创建时的模拟身份名称，历史记录回退原 owner，不随角色切换改变。创建人和创建时间在保存层禁止修改。

| 内容 | 归属 | 规则 |
| --- | --- | --- |
| 客户、联系人、整体背景 | 服务请求 | 各项共用，提交时必填 |
| 服务方式、需求、业务对象 | 申请项 | 根据目录配置显示及校验；只能关联创建时所选客户的对象 |
| 产品版本类型、版本号、节点数 | 目录申请配置 / 申请项参数 | 安装类默认必填；节点数须正整数，不是计费人天 |
| 材料名称、说明、必填性、模板 | 目录申请配置 | 在目录详情维护，与计价字段分离 |
| 材料文件列表 | 申请项 | 多文件独立并存，保存真实字节；不采用替换或历史版本路线，不需要“已填写”确认 |
| 配置版本和模板 | 申请项快照 | 新增项时复制，目录后续修改不回写历史项 |
| 人天与权益扣减 | 后续 PMO 评估 | 申请阶段不强制填写通用计费数量 |

安装类预置用户提供的售前向交付移交模板；其他服务预置可本机编辑的 Markdown 需求说明模板。可在目录中上传 Word、PDF、表格等模板替换预置版本。

## 校验与持久化

- 所有申请项都需有需求说明和有效服务方式。配置中启用的额外参数必须填写。
- 必填材料至少有一个已保存的上传文件或非空在线文档即满足材料齐全校验；删除最后一份文件并保存后恢复待补充，阻止提交。删除填写确认字段及相关提交条件，历史记录中的该标记不再参与判断。仅下载或载入模板但未保存不满足要求；材料齐全不代表 PMO 已评估通过。
- 材料文件列表逐一展示，支持一次上传多个文件，同名文件也独立保留。在线新建新增文件，在线编辑仅修改明确选中的文档。上传其他文件不会丢弃未保存在线正文。删除需确认并在保存材料后生效，取消材料修改则保留原文件；提交后只读，不可删除。
- 兼容历史 versions 数据，所有旧版本作为独立文件展示，保存时转换为 files 列表，不丢弃历史文件字节。
- 提交时再次核查客户、联系人、服务目录和已选择业务对象是否存在、启用及客户归属一致。
- 业务对象没有数量最低限制；不能拿业务对象关联代替后续服务依据关联。
- 单文件上限 20 MB，支持 doc/docx/pdf/xls/xlsx/csv/txt/md/png/jpg/jpeg。拒绝空文件；不提供恶意文件扫描，正式系统需要服务端校验和扫描。
- 本机浏览器 IndexedDB 存储请求、申请配置及文件 Blob；同一请求及其材料一次事务写入，写入成功才显示保存成功。
- 保存失败保留弹窗填写内容，提示重试。材料弹窗内有未保存修改时，关闭须确认放弃；保存成功后关闭弹窗，更新对应申请项的缺项提示。材料编辑、模板正文提取与文件持久化均在本机完成，不发送到云端。
- 关闭浏览器后可在同一浏览器、同一地址继续已保存草稿；清除站点数据、隐私模式回收或存储配额限制可能导致资料丢失。此方案不是正式服务端存储。
- 提交后本版只读展示，不实现申请变更、评估退回、审批及通知；不是线上生产流程。

使用 `lib/service-requests.test.mjs` 覆盖零项阻止提交、1..N 项、重复目录、选填多业务对象、参数规则、材料要求、文件字节克隆、格式及大小限制、配置快照与无效关联。
